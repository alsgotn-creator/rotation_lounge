# 플러팅라운지 — 로테이션 소개팅 진행 웹앱 설계

작성일 2026-10-31 · 상태: 사용자 검토 중

표기: 별도 표시가 없는 항목은 사용자가 직접 정한 것. **[내 판단]** 은 대화 중 제안했고 반대가 없었거나, 빌더가 정해도 되는 수준이라 내가 정한 것.

---

## 1. 무엇을, 왜

진행자(사용자)는 오프라인 로테이션 소개팅(7:7 ~ 9:9)을 정기적으로 운영한다. 지금은 종이 안내문·밸런스게임 카드·최종선택 카드·연애코드 문항지를 인쇄해서 쓰고, 시간·좌석·결과 집계를 손으로 한다. 이 앱은 그 진행을 **참가자 폰 + 진행자 큰 화면**으로 옮긴다.

성공 기준:
- 참가자는 행사 전에 집에서 링크로 등록을 끝내고, 현장에서는 따로 입력하지 않는다.
- 진행자는 버튼 몇 개로 단계·라운드·결과 공개를 넘기고, 모두의 화면이 동시에 바뀐다.
- 분위기는 **풋풋하고 사랑이 느껴지되 고급스럽게**. 귀엽지만 유치하지 않다.

### 목표
- 사전 등록 + 연애관 15문항 → 연애 컬러(16유형) + 가장 비슷한 이성 추천
- 대기실(메타버스 느낌): 캐릭터 + 키워드만
- 대화 라운드: 타이머, "몇 번째 이성", 7분째 상대 정보 공개, 선택형 페어 게임
- 라운드 후 익명 롤링페이퍼, 마무리 단계에 본인만 열람
- 최종선택(최대 N명), 상호 선택만 매칭 통보
- 진행자 큰 화면 + 진행자 조작 화면

### 하지 않는 것 (non-goals)
- 연락처 교환 기능: 매칭된 커플의 번호는 **진행자가 직접 전달**한다. 앱은 연락처를 받지도 보여주지도 않는다.
- 결제·참가 신청 접수, 채팅, 사진 업로드
- 현장 QR 입력
- 짝 없는 사람(인원 불균형)을 위한 별도 기능: 그 라운드는 그냥 쉰다.
- 자동 진행: 어떤 단계도 시간이 됐다고 저절로 넘어가지 않는다(타이머 종료 알림만).

### 실패로 볼 것 (anti-goals)
- 파스텔·만화·픽셀 등 유치한 느낌 (사용자가 여러 번 거절함)
- 사용자의 기존 인쇄물(흑백 + 분홍빨강 에디토리얼) 디자인을 따라 하는 것. 그 자료는 **내용 출처로만** 쓴다.
- 누가 나를 몇 명 골랐는지, 롤링페이퍼를 누가 썼는지가 어떤 경로로든 드러나는 것
- 나이·직업 등 인적사항이 맞은편 상대가 아닌 사람에게, 또는 7분 전에 보이는 것

## 2. 제약

- **스택:** Next.js(App Router), Vercel 배포, Supabase(Postgres + Realtime). 사용자 결정.
- **비용:** 월 0원 목표(무료 티어).
  - Supabase 무료 프로젝트는 1주일 접속이 없으면 일시정지된다 → 하루 1회 keep-alive 요청(Vercel Cron)으로 막는다.
  - Vercel Hobby는 약관상 비상업용. 유료 행사에 본격적으로 쓰면 Pro($20/월) 전환을 진행자가 판단(안내만 함).
- **규모:** 한 행사 최대 18명 + 진행자. 동시에 여러 행사가 진행될 일은 없다고 본다 **[내 판단]**.
- **기기:** 참가자는 각자 스마트폰. 진행자 큰 화면은 **세로형** 디스플레이. 모든 화면은 세로(portrait) 레이아웃만.
- **언어:** 한국어 단일.

## 3. 행사 흐름

진행자가 단계를 넘기며, 단계는 모든 화면에 보인다:

**시작 전 → 대화 → 최종선택 → 마무리**

1. **행사 전:** 진행자가 행사를 만들면 참가 링크가 생긴다. 카톡 등으로 공유. 링크 페이지에는 행사 안내(시간·장소, 남녀별 입장 시간, 음료 선택, 신분증 지참, 준비물)가 함께 나온다.
2. **사전 등록**(집에서): 기본 정보 → 15문항 → 연애 컬러 결과 → 캐릭터 고르기.
3. **시작 전**(현장): 같은 링크로 들어오면 대기실. 참가자가 자기 테이블을 눌러 착석 등록.
4. **대화:** 진행자가 라운드 시작 → 타이머 진행 → 7분째 정보 공개 → 종료 알림 → 롤링페이퍼 작성 → 진행자 "다음 라운드"(남자 이동). 반복.
5. **최종선택:** 진행자가 단계를 넘기면 참가자가 최대 N명 선택. 진행자는 결과를 즉시 본다.
6. **마무리:** 진행자가 약 30분 뒤 "결과 공개"를 누르면 매칭 통보가 간다. 롤링페이퍼도 이 단계에서 열린다.

## 4. 화면별 상세

시안: `.superpowers/brainstorm/2664-1793417169/content/` (gitignore됨). 최신본 기준 파일명을 괄호에 적었다.

### 4.1 스플래시 (`splash-v2.html`, A안)
- 사이트 진입 후 로딩 동안 표시.
- 미드나잇 배경 + 반짝이는 작은 별.
- 상단에 **플러팅 / 라운지** 두 줄(3글자씩), 크게(폰 기준 약 76px), 손글씨체, 로즈골드 그라데이션이 글자 위를 지나가는 반짝임.
- 아래에 로즈골드 선 일러스트: 카페 테이블에서 마주 보는 남녀(Higgsfield 생성, 투명 PNG, job `54867cda-4cbd-46a9-9aed-8bb5b514fb2d`).
- 하단에 가는 로딩 바. 캐릭터는 넣지 않는다.

### 4.2 사전 등록 (`prereg.html`)
1. **기본 정보:** 닉네임, 성별, 나이, MBTI, 직업, 사는 곳, 나만의 키워드 1~2개. 안내문 "나이·직업·사는 곳·MBTI는 대화 7분째, 맞은편 상대에게만 보여요."
2. **연애관 15문항:** 한 화면에 한 문항. 5단계 동그라미(양 끝이 크고 가운데가 작음, "전혀 아니에요 ↔ 완전 그래요"). 누르면 자동으로 다음 문항, 이전으로 돌아가기 가능. 진행도 "6 / 15".
3. **나의 연애 컬러:** 글자 없이 빛나는 색 구슬 + 성향 문장 4줄. "당신과 가장 비슷한 사람은…" 칸은 전원 등록 후(진행자가 열면) "○호분이에요!"로 채워진다.
4. **캐릭터 고르기:** 내 연애 컬러로 정해진 색 안에서 **몸 모양**과 **소품**을 각각 고른다(4.9 참고).
- 등록 후 같은 링크로 다시 들어오면 수정 가능(시작 전 단계까지) **[내 판단]**.

### 4.3 대기실 (`lounge-mix.html`)
- 행사 이름·시간·인원.
- 참가자 캐릭터들이 떠 있고, 각 캐릭터 옆에는 **나만의 키워드만**. 이름·나이 등은 없음.
- "나"는 조금 더 크게.
- 하단 카드: 내 연애 컬러 구슬 + 성향.
- 시작 전 단계에서는 여기서 테이블 고르기로 진입.

### 4.4 좌석
- 테이블 배치는 직사각형(행사장이 바뀔 수 있어 일단 직사각형 고정). 세로형 큰 화면 기준 **오른쪽 열 1~4번(위→아래), 왼쪽 열 5~N번(아래→위)**, 그래서 번호순 이동이 시계방향이 된다.
- 참가자가 1라운드 전에 자기 테이블을 누른다. 이미 같은 성별이 고른 자리는 막는다.
- 여자는 고정, 남자는 "다음 라운드"마다 테이블 번호 +1(마지막 → 1번).
- 테이블 수 = max(남, 여). 인원이 안 맞으면 상대가 없는 사람은 그 라운드 쉰다.
- 진행자는 좌석을 수정할 수 있다(잘못 앉은 경우).
- **참가 인원은 현장에서 테이블을 누른 사람만으로 계산한다**(사용자 결정). 등록만 하고 안 온 사람은 진행자가 제외한다. 등록 없이 온 사람은 현장에서 같은 링크로 들어와 등록한다(QR 입력 화면을 따로 만들지 않음). 호 번호·테이블 수·"N명 중"·최종선택 그리드·추천은 모두 착석 인원 기준.
- 라운드 수 기본값 = max(남, 여) (모두 한 번씩 만남) **[내 판단]**. 진행자는 언제든 대화 단계를 끝낼 수 있다.

### 4.5 대화 라운드 – 참가자 폰 (`host-and-round-v2.html`)
- 상단: "Round 3", **"3번째 이성 · 7명 중"** 상자.
- 원형 타이머: "남은 시간" + 굵은 고딕 숫자(Pretendard 800, tabular-nums).
- 상대 카드: 상대 캐릭터 + "남1호" + 키워드. 7분 전에는 "7분째 공개돼요" 안내.
- **7분째**: 상대의 나이·직업·사는 곳·MBTI + 연애 컬러/성향이 "방금 공개" 표시와 함께 나타난다. **오직 맞은편 상대의 폰에만.**
- 한 번 공개된 정보는 **행사가 끝날 때까지 계속 볼 수 있다**(사용자 결정). 최종선택 그리드에서 이미 만난 사람을 누르면 그 정보가 보인다. 만나지 않았거나 7분 전에 라운드가 끝난 상대의 정보는 끝까지 보이지 않는다.
- 하단 "✦ 같이 해보기" (선택, 4.7).
- 시간 종료 시 알림 → 롤링페이퍼 작성 화면으로.
- 쉬는 사람: "이번 라운드는 쉬어가요" 정도만.

### 4.6 진행자 큰 화면 + 조작 화면
- **큰 화면(세로형, 버튼 없음):** 단계 표시(시작 전·대화·최종선택·마무리), Round n / N, 큰 타이머와 진행 막대(7분 지점 "정보 공개" 표시), 직사각형 좌석도(테이블마다 "여1호 / 남6호" + 캐릭터 얼굴), 쉬는 사람 표시, 시계방향 이동 안내.
- 큰 화면 외 단계에서는 대기실 전경(캐릭터들), 최종선택 중엔 "선택 중 n/N명 완료", 마무리에선 결과 공개 전 대기 화면 **[내 판단]**. 큰 화면에는 매칭 결과를 띄우지 않는다 **[내 판단: 개인 결과이므로]**.
- **조작 화면(진행자 폰/노트북):** 다음 단계, 라운드 시작, 다음 라운드(남자 이동), 일시정지/재개, 라운드 시간 설정(기본 15분, 12분 등), 좌석 수정, 최종선택 인원 N(2 또는 3), 추천 공개, 결과 공개, 롤링페이퍼 검토(부적절한 글 숨김), 최종선택 결과 전체 보기, 매칭 커플 목록(번호 전달용).

### 4.7 선택형 페어 게임
- 대화 중 둘 중 누구든 "같이 해보기"를 누르면 카드 한 장이 두 사람 폰에 동시에 뜬다.
- 둘 다 답하면 답이 나란히 공개된다. 필수 아님, 언제든 닫을 수 있다.
- 카드 종류: 밸런스게임(vol.1·vol.2), 연애 토크 카드, 시나리오 질문 — 사용자의 기존 인쇄 자료 내용을 그대로 옮긴다.
- **"너는? 꼭 되물어주기" 문구는 넣지 않는다.**
- 카드는 진행자가 관리 화면에서 추가/수정할 수 있다 **[내 판단]**. 초기 데이터는 시드로 넣는다.

### 4.8 롤링페이퍼 (`paper-and-choice.html`)
- **쓰기:** 매 라운드 종료 후 방금 대화한 상대에게. 상대 캐릭터 + "남1호에게 한마디", 크림색 종이 위 손글씨 입력. 안내: 익명으로 전달, 연락처 금지. 건너뛰기 가능 **[내 판단]**.
- 연락처 패턴(전화번호, 카톡ID·인스타 형태 등)은 입력 시 막는다 **[내 판단]**.
- 작성 중에 진행자가 "다음 라운드"를 눌러도 작성 화면은 닫히지 않고 제출할 때까지 유지된다. 다음 라운드 화면은 제출 후 넘어간다 **[내 판단]**.
- **열람:** 마무리 단계가 시작되는 순간부터(결과 공개 전에도), **받은 본인만** **[내 판단]**. 크림색 편지지 한 장 위에 메시지가 무작위 위치·각도·크기·잉크색(버건디·네이비·브라운·퍼플)으로 흩어진 손글씨, 사이사이 작은 하트. 목록으로 나열하지 않는다. "6장 · 누가 썼는지는 비밀이에요".
- 작성자 정보는 DB에 저장되지만(검토용) 참가자 쪽 API로는 절대 내려가지 않는다. 진행자는 내용을 보고 숨길 수 있다.

### 4.9 캐릭터
- 스타일: 유광 구름-젤리 몸 + 큰 반짝이는 눈(Higgsfield 시안 **1번 표정 + 5번 질감**), 2등신, 짧은 팔다리.
- **색 = 연애 컬러(16색).** 참가자는 그 색 안에서 **몸 모양 3종**과 **소품**을 각각 고른다(사용자: "몸 모양, 소품 다 다르게 가능하도록").
- 애니메이션은 **영상이 아니라 이미지 방식**(사용자 결정, 비교 시안 `anim-compare.html`):
  - 캐릭터마다 위치가 정확히 겹치는 투명 PNG 3장: 기본 / 웃음 / 눈 감음.
  - 몸은 CSS로 숨쉬기(scaleX 1.035 / scaleY 0.965, 3.6초), 얼굴 영역만 마스크로 웃음(7초 주기)·깜빡임(4.6초 주기) 프레임을 겹친다. 캐릭터마다 지연을 달리해 동시에 움직이지 않게.
- 에셋 생성 **[내 판단]**: 몸 = 16색 × 3모양 × 3프레임 = 144장(Higgsfield `gpt_image_2_5`, 투명 배경, 약 36크레딧). 소품은 몸과 별도의 투명 PNG 레이어로 만들어 몸 모양별 기준점에 얹는다(색과 무관하게 재사용, 소품 5종 + "없음"). 384px WebP로 변환해 저장(장당 약 20~30KB).
- 몸 모양 3종 초안 **[내 판단]**: 구름(기본), 동글(둥근 찹쌀떡형), 물방울. 소품 5종 초안: 리본, 꽃, 별, 하트, 작은 왕관.

### 4.10 최종선택과 결과
- 최종선택: 이성 전원의 캐릭터 + "○호" + 키워드를 3열 그리드로. 고르면 로즈골드 빛 + ♥, "2 / 3" 카운터. 0명도 가능. "선택 완료" 후 수정은 단계가 끝나기 전까지 가능 **[내 판단]**.
- 진행자는 선택 즉시 전체 결과를 본다.
- 결과 공개(진행자 버튼, 약 30분 후):
  - 서로 고른 경우만: 두 캐릭터 사이 ♥, "남1호님과 매칭되었어요", "진행자가 연락처를 직접 전해드릴 거예요". 여러 명과 매칭되면 각각 표시.
  - 매칭 없음: "이번엔 인연이 닿지 않았어요" + "내 롤링페이퍼 보기".
  - 나를 고른 사람 수·누구인지는 어디에도 나오지 않는다.

## 5. 연애 컬러 (16유형)

4개 축, 각 축 양쪽 성향:

| 축 | 한쪽 | 다른 쪽 |
|---|---|---|
| 거리감 | 늘 함께 | 각자 시간도 소중 |
| 표현 | 솔직하게 직진 | 천천히 은근하게 |
| 데이트 | 둘만의 아늑한 데이트 | 바깥 나들이 |
| 미래 | 결혼·미래 계획형 | 지금 이 순간형 |

- 조합 16가지 = 16색. **화면에는 실제 색만** 보이고 알파벳·색 이름 텍스트는 없다. 성향은 짧은 문장 4줄로.
- 문항: 축마다 3~4문항, 총 **15문항**, 5점 척도. 사용자의 "나의 연애 코드" 10문항을 뼈대로 쓴다. 일부는 역문항.
- 축 점수 = 해당 문항 평균(역문항 뒤집음). 동점(정확히 중간)은 정해진 기본값 쪽으로 **[내 판단]**.
- 16색 팔레트: 미드나잇 배경 위에서 서로 구분되고 고급스러운 보석/와인 톤으로 빌더가 정한다 **[내 판단]**. 축 두 개(거리감·표현)로 색상 계열, 나머지 두 개로 명도·채도를 나누면 "비슷한 사람은 비슷한 색"이 된다.
- **추천:** 15문항 응답 벡터의 거리(유클리드)가 가장 가까운 **이성** 1명. 진행자가 "추천 공개"를 누르면(보통 전원 등록 후) 각자 화면에 "당신과 가장 비슷한 사람은 ○호분이에요!". 그 전엔 "모두 등록하면 알려드릴게요".

문항 초안 (빌더는 이 문구를 쓰되, 진행자가 나중에 고칠 수 있게):

| # | 축 | 문항 |

| 7 | 표현 | 말보다 행동으로 마음을 보여주는 편이에요. (역) |
| 8 | 표현 | 먼저 연락하거나 고백하는 게 어렵지 않아요. |

## 7. 기술 설계 (빌더 참고)

대부분 **[내 판단]**. 빌더가 더 나은 방법이 있으면 바꿔도 되지만, 4장의 동작은 지켜야 한다.

### 인증
- 참가자: 로그인 없음. 사전 등록 완료 시 참가자별 비밀 토큰 발급 → 쿠키 + "내 링크"로 재접속. 다른 기기에서 들어오면 닉네임 + 간단한 4자리 PIN으로 복구.
- 진행자: 행사별 관리자 비밀번호(환경변수 또는 행사 생성 시 설정). 큰 화면은 읽기 전용 토큰 URL.

### 데이터 (Supabase Postgres)
- `events` — 이름, 일시·장소·안내문, 단계(phase), 라운드 시간, 최종선택 N, 추천 공개 여부, 결과 공개 여부
- `participants` — event, 성별, 번호(호), 닉네임, 나이, 직업, 사는 곳, MBTI, 키워드[], 응답[15], 연애 컬러(0~15), 캐릭터(모양, 소품), 토큰 해시
- `seats` — 참가자 ↔ 1라운드 기준 테이블 번호
- `rounds` — 번호, 시작 시각, 일시정지 누적, 상태. 타이머는 서버 시각 기준(시작 시각 + 경과)으로 계산해 기기 간 어긋남 방지.
- `game_cards` / `game_sessions` / `game_answers`
- `notes`(롤링페이퍼) — 작성자, 받는 사람, 라운드, 내용, 숨김 여부
- `choices` — 선택자, 대상
- 참가자 번호(호): 성별별 등록 순서로 자동 부여, 진행자 수정 가능.

### 비공개 규칙 (가장 중요)
- 인적사항(나이·직업·사는 곳·MBTI)과 롤링페이퍼 작성자, 다른 사람의 선택은 **클라이언트가 직접 테이블을 읽지 못하게** 한다(RLS로 차단). 서버(Route Handler / Server Action)가 "요청자가 이 사람과 맞은편에 앉았던 라운드가 있고, 그 라운드의 경과 시간이 7분 이상(일시정지 제외)에 도달했는지"를 확인한 뒤에만 인적사항을 내려준다. 공개 이력은 `reveals`(열람자, 대상, 라운드)로 기록해 두면 간단하다.
- 매칭 결과도 서버가 결과 공개 이후에만 본인 몫만 계산해 내려준다.

### 실시간
- Supabase Realtime 채널(행사별)로 단계·라운드·타이머 상태·게임 카드 변경을 브로드캐스트. 민감 데이터는 채널에 싣지 않고 "변경됐다" 신호만 → 클라이언트가 서버에 다시 요청.

### 개인정보
- 등록 첫 화면에 개인정보 수집·이용 동의 체크(필수). 수집 항목, 목적(행사 진행), 보관 기간(행사 후 30일)을 적는다.
- 행사 종료 30일 뒤 해당 행사의 참가자·롤링페이퍼·선택·게임 데이터를 자동 삭제(Vercel Cron)(사용자 결정). 행사 간 프로필 재사용은 하지 않는다.

### 기타
- Vercel Cron 하루 1회로 Supabase keep-alive.
- 캐릭터·일러스트 이미지는 `public/`에 정적 파일(WebP)로.
